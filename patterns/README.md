# Реестр паттернов

Детекторы анализа задаются JSON-файлами в этом каталоге — код менять не нужно.
Файлы кладутся просто подряд: каждый `*.json` подхватывается автоматически.
Реестр перечитывается на каждый запрос анализа — рестарт сервера не нужен.

## Правила для клиента

- Менять можно `enabled`, содержимое `params` и `detector`.
- `id`, `kind`, `output` не трогать — их понимает движок.
- `detector` — какой движок выполняет файл: `fixed-size`, `length-prefixed`
  или `sync-word`. Свой `id` с известным `detector` заводится без правки кода.
  Без `detector` три штатных `id` работают как раньше (legacy).
- Невалидный JSON или неизвестные обязательные поля: файл пропускается,
  в лог сервера пишется причина **с именем файла**. Сервер при этом стартует нормально.

## Формат файла

```json
{
  "id": "my-sizes",
  "name": "Человеческое имя",
  "kind": "framing",
  "detector": "fixed-size",
  "version": 1,
  "enabled": true,
  "params": { "...": "..." },
  "output": { "framing": "fixed", "confidence": "const" }
}
```

Обязательные поля: `id`, `kind`, `params` (объект). Остальное опционально.
Машиночитаемая схема — `schema.json` (JSON Schema, draft-07); сам файл
схемой не грузится как паттерн.

## Параметры по детекторам

### fixed-size.json
- `sizes`: кандидаты размера сообщения, перебираются по порядку.
- `min_messages`: минимум сообщений (длина потока / размер).
- `confidence`: уверенность гипотезы при срабатывании.

### length-prefixed.json
- `prefix_bytes`: варианты длины префикса. `1` читается как u8,
  `2` — как u16be (`prefix_encoding` фиксирует это соответствие).
- `max_len`: предельная длина payload, больше — обрыв цепочки.
- `min_messages`, `min_rate`: минимум сообщений и доля валидных шагов.
- `confidence`: уверенность гипотезы при срабатывании.

### sync-word.json
- `words`: маркеры, hex-пары через пробел (`"AA 55"`).
- `min_count`: минимум вхождений маркера в потоке.
- `confidence`: уверенность гипотезы при срабатывании.

## Файлы под термостенд (`thermo-*`)

Наш трафик (`sample_protocol/research/*`, `additional/*`) — каждое сообщение
начинается с магии `A6 5C`, стоковые маркеры (`AA 55` и т.д.) там не встречаются.
Поэтому поверх трёх базовых лежат tuned-файлы, все на тех же движках
(новый код не нужен, подхват автоматический):

- `thermo-magic.json` — `A6 5C`, `min_count: 2`, `confidence: 0.95`. Главный паттерн, стреляет на любой нашей записи.
- `thermo-magic-v0.json` — `A6 5C 00` (магия + нулевой байт), `confidence: 0.9`. Строже, подтверждает версию фрейминга.
- `thermo-small-frames.json` — `fixed-size [5, 6]`, `min_messages: 4`, `confidence: 0.7`. Минимальный запрос 5 байт, короткие команды 6 байт.
- `thermo-mid-frames.json` — `fixed-size [9, 12, 18]`, `confidence: 0.65`. Типичные длины ответов.
- `thermo-len-u8.json` / `thermo-len-u16.json` — `length-prefixed`, `confidence: 0.55/0.5`. Мягкий fallback; на потоках с магией не стреляют (первый байт `A6` слишком велик), только страховка.

Сортировка гипотез — по `confidence`: sync-маркеры всегда выше fixed/length fallback'ов.
